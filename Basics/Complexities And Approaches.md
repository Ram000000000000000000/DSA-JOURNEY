# 📊 Time & Space Complexity + Approaches

---

## **⏱️ Time Complexity**
Time complexity measures how fast an algorithm runs as input size increases.

### **Common Complexities**
- **O(1)** → Constant (fastest)
- **O(log n)** → Logarithmic (Binary Search)
- **O(n)** → Linear
- **O(n log n)** → Sorting
- **O(n²)** → Nested loops (slow)
## ⏱️ Time Complexity Order (Best → Worst)

1. **O(1)** → Constant  
2. **O(log n)** → Logarithmic  
3. **O(n)** → Linear  
4. **O(n log n)** → Linearithmic  
5. **O(n²)** → Quadratic  
6. **O(n³)** → Cubic  
7. **O(2ⁿ)** → Exponential  
8. **O(n!)** → Factorial (worst)

---

## 💡 Understanding Growth

- **O(1)** → No matter input size, time is constant  
- **O(log n)** → Very fast (Binary Search)  
- **O(n)** → Scales linearly  
- **O(n log n)** → Efficient sorting  
- **O(n²)** → Nested loops (slow)  
- **O(2ⁿ), O(n!)** → Extremely slow, avoid if possible  

---

## 🚀 Key Learning
As input size increases:
O(1) < O(log n) < O(n) < O(n log n) < O(n²) < O(n³) < O(2ⁿ) < O(n!)

---

## **🧠 Space Complexity**
Space complexity measures how much extra memory an algorithm uses.

- **O(1)** → No extra space
- **O(n)** → Extra memory grows with input

---

## **🔍 Problem Solving Approaches**

### **❌ Brute Force**
- Try all possible solutions  
- Easy to think  
- Usually slow (high time complexity)  

👉 Example: checking all pairs in an array  

---

### **⚡ Optimized Approach**
- Reduce unnecessary work  
- Use techniques like:
  - Hashing  
  - Sliding Window  
  - Two Pointers  

👉 Goal: improve time/space efficiency  

---

## **💡 Key Learning**
Always:
1. Start with brute force  
2. Understand why it is slow  
3. Then optimize step by step  

🚀 This builds strong problem-solving skills.
